# 季一藕「射箭切磋 + 10次后狩猎」互动：现状支持度评估与落地计划

## 1. 需求拆解（你提出的目标）

1. 新增互动：与季一藕去关山射箭馆比拼箭术。  
2. 每次射箭比拼随机输赢（且与居民综合水平/准头/阅历/能力有关）：
   - 季一藕赢：居民 +20 金钱、+10 阅历。
   - 季一藕输：居民 -10 金钱、准头 +20。
3. 累积 10 次后触发后续邀约：季一藕邀请去郊外林子狩猎。
4. 狩猎结果按概率分档，受角色综合属性影响：
   - 较好：野山鸡和兔子（阅历+25，金钱+50，体力-15）
   - 极好：野鹿或山雀（阅历+40，金钱+100，体力-30）
   - 一般：竹鼠（阅历+15，金钱+30，体力-10）
   - 较差：蘑菇野菜笋子（阅历+10，金钱+15，体力-5）
   - 极差：被黑熊追赶（称号“喜欢做梦的逃兵”，体力-30，阅历+50）

---

## 2. 当前项目已支持（可直接复用）

### 2.1 有“射箭”场景与能力相关命中逻辑

- 设施页已有“无宁箭馆”小游戏，有体力消耗、射箭流程与结算。
- 命中率已经和 `ability` 挂钩（不是纯随机），说明“属性影响概率”基础能力已存在。

### 2.2 有 NPC 互动入口、事件触发与每日限制体系

- `NPCList` 已支持对 NPC 发起 `talk / gift / event` 三类互动。
- `interactWithNPC` 已有“每日互动限制”的状态管理，可用于限制射箭次数或狩猎触发频率。

### 2.3 有通用事件效果落地能力

- `handleEventOption` 支持统一结算：金钱、能力、体力、阅历（experience）、关系变化、加物品、设置/累计 flags。
- 这意味着“射箭计次”“10次后解锁”“狩猎结果结算”都能以统一管道入账。

### 2.4 有成就系统可借用作“称号落地”

- 目前没有独立“称号”字段，但已有成就系统与弹窗，可把“喜欢做梦的逃兵”先作为隐藏成就（或后续再抽象为 title 系统）。

---

## 3. 当前不支持 / 支持不足（与你需求直接相关）

### 3.1 缺少“准头”独立数值

- 玩家属性里目前没有 `accuracy/准头` 字段，只有 `ability/experience` 等。
- 若要精确实现“输了获得准头+20”，需新增玩家属性与显示入口。

### 3.2 NPC 对战没有“双方属性对抗模型”

- 现有射箭玩法是“玩家打靶得分”，并非“玩家 vs 季一藕”对战。
- 需要增加 NPC 射箭能力基线（固定值或成长值）与胜负判定模型。

### 3.3 缺少“概率分层 + 属性加权”的统一计算模块

- 当前事件数据多是静态效果，不自带复杂概率表与动态加权。
- 你的需求要求将“综合水平、准头、阅历、能力”共同映射到结果概率，建议独立模块化。

### 3.4 缺少“连续里程碑链路”专用模块

- “累计 10 次射箭 -> 解锁狩猎邀请”可用 flags 实现，但目前没有专门的“互动链任务/里程碑引擎”，逻辑会分散。

### 3.5 “称号”暂未产品化

- 项目内常用“日志里写获得称号”表达；若你要长期做类似玩法，建议补一层正式的 Title 系统（可展示、可筛选、可条件解锁）。

## 4. 新增模块计划（优先保证可扩展）

> 目标：本次先完成“季一藕射箭与狩猎”；架构上可扩展到任意 NPC 的“对抗类互动链”。

### 模块 A：NPC 对抗互动引擎（核心）

**建议新增：** `src/services/npcDuelEngine.ts`

职责：
- 输入：`npcId`、`duelType`（archery）、玩家状态、NPC 基线配置。
- 输出：胜负结果、得分摘要、奖励 effect、日志文案、计次变化。

建议接口：
- `simulateNpcDuel(params): DuelOutcome`
- `calcArcheryWinRate(player, npc, modifiers): number`

扩展性：
- 后续可新增 `duelType: chess | debate | martial`，复用同一引擎。

### 模块 B：互动链路配置（里程碑解锁）

**建议新增：** `src/data/npcInteractionChains.ts`

职责：
- 配置 “某互动累计 X 次 -> 解锁下一阶段事件”。
- 示例：`ji_yi_ou_archery_duel_count >= 10` 解锁 `ji_yi_ou_hunt_invitation`。

扩展性：
- 后续可用于“完成N次送礼解锁支线”“连续聊天触发密谈”等。

### 模块 C：狩猎结果概率表与加权器

**建议新增：**
- `src/data/huntOutcomeTables.ts`
- `src/services/huntResolutionEngine.ts`

职责：
- 定义基础概率档位（极好/较好/一般/较差/极差）。
- 使用玩家属性（综合水平、准头、阅历、能力）计算权重偏移。
- 最终抽样并返回结果 effect。

扩展性：
- 支持季节、天气、道具、NPC 好感的权重修正。

### 模块 D：玩家“准头”属性接入（最小侵入）

**改动点：**
- `src/types/game.ts`：给 `PlayerStats` 增加 `accuracy`。
- `src/store/gameStore.ts`：初始值、存档兼容、结算写入。
- `src/components/StatsDisplay.tsx`：展示准头。

扩展性：
- 后续可接入其他系统（投壶、打猎、远程武器玩法）。

### 模块 E：称号系统（可选但推荐）

**方案 1（低成本）：** 先用隐藏成就承载称号。  
**方案 2（长期）：** 新增 `titles` 数据结构，支持“当前佩戴称号”。

建议本期采用方案 1，降低改动风险；下一期再抽象正式称号系统。

## 5. 分阶段执行计划（从可上线到可扩展）

## Phase 0：方案对齐（0.5 天）

- 确认“输赢奖励是否反直觉”是否按你原文执行（当前文案是“季一藕赢了，玩家获利；季一藕输了，玩家扣钱但加准头”）。
- 确认“综合水平”的具体公式（例如：`综合=0.35*ability+0.25*accuracy+0.2*experience层级+0.2*relation`）。

## Phase 1：最小可用版本 MVP（1~1.5 天）

1. 新增 `accuracy` 属性并打通展示。
2. 新增“与季一藕射箭切磋”互动按钮（NPC 页面）。
3. 实现一次切磋结算：
   - 胜负概率受 `ability + accuracy + experience` 影响；
   - 按你给定数值发放奖励/惩罚；
   - `flags['ji_yi_ou_archery_duel_count']++`。
4. 达到 10 次后写入可触发状态 `flags['ji_yi_ou_hunt_unlocked']=true`。

**验收口径：** 能稳定打完 10 次并出现狩猎邀请入口。

## Phase 2：狩猎结果系统（1 天）

1. 接入狩猎概率表（5 档结果）。
2. 用属性加权调整结果概率。
3. 落地每档效果与日志文案。
4. “极差”结果先以隐藏成就发放“喜欢做梦的逃兵”。

**验收口径：** 多次模拟抽样能观察到高属性角色出现“较好/极好”占比提升。

## Phase 3：可扩展重构（1~1.5 天）

1. 把切磋与狩猎逻辑沉淀到 `npcDuelEngine / huntResolutionEngine`。
2. 用 `npcInteractionChains` 配置化里程碑，不再散落在页面组件。
3. 增加简单开发校验（配置合法性、概率总和、奖励字段合法）。

**验收口径：** 新增第二个 NPC 的同类玩法时，仅需加配置，不改核心流程。

## 6. 风险与规避

- **风险 1：属性膨胀导致概率失衡。**  
  规避：概率计算统一做 clamp（如 5%~95%），并保底随机性。

- **风险 2：存档兼容问题（新增 accuracy）。**  
  规避：读取旧存档时默认补 0 或基础值。

- **风险 3：逻辑散落导致后续难维护。**  
  规避：第一版即把核心计算放 service，UI 只负责触发和展示。

---

## 7. 建议的实现顺序（实际开工）

1. 先做 `accuracy` 字段 + 存档兼容。  
2. 再做“季一藕射箭切磋”单次结算。  
3. 接入“累计10次解锁狩猎”。  
4. 最后做“狩猎概率表 + 属性加权 + 极差称号”。

这样即使中途停在第 2~3 步，也能先上线一个完整可玩的阶段版本。
