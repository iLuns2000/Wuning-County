# 无宁县志：新手引导功能实现计划（分析 + 落地方案）

## 1. 项目现状分析（为什么会感觉“缺少引导”）

结合当前代码结构，项目已经有“目标系统”和“操作系统”，但缺少“逐步提示系统”：

1. **入口页只做身份选择，没有玩法路径提示。**
   - 首页强调“选身份开局”，但没有告诉玩家“第一天先做什么”。
2. **游戏主页面模块很多，信息密度高。**
   - 主界面含工作、市场、探索、政务、韭菜园、背包、任务等多入口，新玩家容易不知从哪开始。
3. **任务链已经存在，但触达感较弱。**
   - `tasks.ts` 的主线任务写得完整，但玩家需要主动去任务页查看，缺少“就地提示 + 一键跳转 + 完成反馈”。
4. **已有弹窗体系成熟，适合承载引导。**
   - 项目本身大量使用 modal（如设置、市场、韭菜园帮助、活动等），说明技术栈和交互习惯都支持引导系统扩展。

> 结论：问题不是“没有任务内容”，而是“没有把任务和操作路径在玩家决策点上显性化”。

---

## 2. 目标定义（引导功能要解决什么）

### 核心目标
- 让新玩家在前 3～5 天内明确：**现在该做什么、做完有什么好处、下一步在哪里**。

### 可量化指标（建议）
- 新档 Day1 完成至少 1 次有效行动（工作/任务特殊行动/市场）比例提升。
- 新档 Day3 仍留存比例提升。
- “首次打开任务页时间”提前到 Day1。
- 新手引导完成率（完成第一阶段引导）> 70%。

---

## 3. 功能设计总览

建议做成 **“轻量分层引导”**，分 3 层，避免打断感太强：

### A. 首次开局流程引导（强引导，仅首次）
- 触发：`startGame` 后首次进入 `/game`。
- 形式：2～4 步的浮层/聚焦引导（Coach Marks）。
- 内容示例：
  1. 看懂顶部核心资源（体力/金钱/声望）。
  2. 去“任务”看当前目标。
  3. 做一次推荐动作（按身份给建议）。

### B. 任务驱动提示（弱引导，常驻）
- 在主界面增加“当前建议”卡片：
  - 显示当前任务目标、下一步推荐操作、一键跳转按钮。
- 当玩家达成阶段条件时，给出非阻断 Toast 奖励反馈。

### C. 上下文帮助（按需）
- 保留自由度，允许“先探索后任务”。
- 当玩家在某模块停留/失败次数较多时，显示“是否查看帮助”入口（如市场、韭菜园、政务）。

## 4. 技术实现方案（按当前项目架构）

## 4.1 状态层（Zustand）扩展

在 `GameState` 增加引导状态字段（建议）：

- `onboardingVersion: number`：引导版本号（便于后续迭代重放）。
- `onboardingCompleted: boolean`：是否完成首次引导。
- `onboardingStep: number`：当前进行到第几步。
- `onboardingDismissed: boolean`：是否跳过本轮引导。
- `hintState: Record<string, { seen: boolean; count: number }>`：模块提示曝光和触发计数。

新增 action：
- `startOnboarding()`
- `nextOnboardingStep()`
- `skipOnboarding()`
- `completeOnboarding()`
- `markHintShown(hintId: string)`

并加入 persist 白名单，保证刷新后不丢。

## 4.2 UI 层新增组件

建议新增组件：`src/components/OnboardingGuide.tsx`

能力：
- 支持遮罩 + 高亮目标元素（通过 `data-guide-id` 找目标）。
- 支持“下一步 / 跳过 / 完成”。
- 支持根据 role 动态文案（县丞/商人/少侠）。

并在 `src/pages/Game.tsx` 中挂载：
- 页面初始化时，若 `!onboardingCompleted` 则展示。
- 给关键按钮打引导锚点：任务按钮、工作按钮、市场按钮、结束一天按钮等。

## 4.3 推荐动作引擎（轻规则）

新增文件：`src/services/guidanceEngine.ts`

输入：
- `GameState`
- 当前 role
- 当前任务

输出：
- `title`：建议标题（例：先完成“第一桶金”）
- `reason`：为什么推荐（缺钱/体力充足/任务差一点）
- `cta`：建议操作（去工作、去市场、去任务）
- `priority`：优先级

第一版用 if/else 规则即可，不需要复杂算法。

## 4.4 主界面“当前建议卡”

在 `Game.tsx` 增加一个轻卡片：
- 文案来自 guidanceEngine。
- 按钮直达对应模块。
- 若玩家关闭卡片，仅当条件显著变化时再次出现（避免打扰）。

## 4.5 文案与可配置化

新增配置文件：`src/data/onboarding.ts`
- 按角色维护引导步骤和文案。
- 把“引导文案”和“引导逻辑”分离，方便后续策划改文案。

---

## 5. 分阶段实施计划（建议 4 个迭代）

### Phase 1：基础引导骨架（1～2 天）
- 扩展 store 字段 + action + persist。
- 接入 `OnboardingGuide` 基础版（静态 3 步）。
- Game 页面增加 anchor 标识。

**验收标准**：新开档必出现引导；可下一步、可跳过、刷新不重置。

### Phase 2：任务联动建议卡（1 天）
- 实现 `guidanceEngine.ts` 基础规则。
- 接入主界面“当前建议卡”。
- 与任务页跳转打通。

**验收标准**：不同角色开局都能看到不同推荐动作。

### Phase 3：上下文帮助（1～2 天）
- 增加模块帮助触发规则（失败次数/停留时长）。
- 在市场、韭菜园等复杂系统旁加“查看引导”入口。

**验收标准**：高频卡点时有提示，正常玩家不被频繁打断。

### Phase 4：数据埋点与优化（1 天）
- 记录引导步骤完成率、跳过率、建议点击率。
- 根据数据调整文案顺序和推荐规则。

**验收标准**：能看见可复盘的数据，支持后续 A/B。

---

## 6. 关键交互细节建议（避免“烦人引导”）

1. **给“跳过引导”且可在设置里“重新体验引导”。**
2. **每次只给一个最小建议**，不要一次塞 5 件事。
3. **奖励反馈即时化**：完成推荐动作后立即提示“你已推进主线”。
4. **移动端优先**：引导气泡避免遮住底部核心操作按钮。

---

## 7. 风险与对应方案

- 风险 1：引导遮挡已有弹窗（事件弹窗、成就弹窗）。
  - 方案：引导优先级低于强事件，检测到强事件时暂停引导。

- 风险 2：老存档兼容问题。
  - 方案：给新字段默认值，`merge` 迁移时兜底。

- 风险 3：玩家反感强制流程。
  - 方案：首次仅 2～4 步，且全程可跳过。

---

## 8. 最小可落地版本（MVP）建议

如果你希望先快速上线验证价值，优先做这 3 件：

1. 首次进入游戏弹出 3 步引导。
2. 主界面加“当前建议卡”（目标 + 一键按钮）。
3. 完成一次建议后给即时奖励提示。

这样工作量可控，但对新手体验提升会非常明显。
