# NPC 事件「好感度门槛未生效」审查与修复计划

## 目标

系统性审查所有 NPC 互动事件，找出“文案标注了好感度门槛，但实际未校验”的情况，并给出可落地的修复方案，避免再次出现同类问题。

---

## 一、先做审查（Audit）

### 1) 数据层审查：找出“写了门槛文案”的事件

优先扫描 `src/data/events.ts` 中 NPC 事件（`npcEvents`）：

- 标题/描述/选项文案包含关键词：`好感`、`需好感`、`解锁`、`>=`、`>`。
- 逐条核对该事件是否存在**真实条件**：
  - 事件触发条件：`triggerCondition.custom` 是否判断 `state.npcRelations[...]`。
  - 选项可选条件：是否有结构化字段（目前无统一字段）。

> 当前已发现的高风险样例（文案有门槛，但代码未见对应校验）：
>
> - `tuyumen_xiada_chat` 选项：`投100文听惊天八卦（好感≥20解锁）`
> - `yingyue_meet_mountain` 选项：`一起走 (需好感>50)`

### 2) 入口层审查：事件是如何被触发的

检查所有触发路径是否统一校验：

- `triggerEvent()`：会校验 `triggerCondition`（包含 `custom`）。
- `triggerSpecificEvent(eventId)`：**当前直接设置事件，不校验触发条件**（高风险）。
- NPC 列表中互动按钮渲染：当前仅检查 `custom` 与 `requiredItems`，其他 `triggerCondition` 字段（如 `minDay/minAbility/...`）未统一复用。

### 3) 展示层审查：选项是否可点击

`EventModal` 当前仅对钱/体力消耗做禁用逻辑，不支持“关系门槛”禁用。

结论：即便事件级触发做了校验，**选项级门槛**如果只是写在文案里，依然会被点到。


### 4) NPC 互动动作门槛审查（新增）

除事件本身外，还需检查 NPC 日常互动动作（如：闲聊、送礼、互动按钮）是否存在门槛提示与实际校验不一致：

- 互动入口按钮是否按门槛隐藏/禁用；
- 点击后是否再次做服务端/状态层校验（防止绕过 UI）；
- 门槛失败时是否给出明确原因（如好感不足、天数不足、道具不足）。

---

## 二、再做修改（Fix）

### 方案 A（推荐，先快修）：补齐最小可用约束

1. **给 `triggerSpecificEvent` 加统一条件校验**（与 `triggerEvent` 共用同一判断函数）。
2. **把明确有门槛的选项改成真实判断**：
   - 先在选项点击前做关系检查，不满足则 toast/日志提示并禁止执行。
3. 对已识别的高风险事件先修复（土御门/影月），快速止血。

优点：改动小，短期见效快。

### 方案 B（推荐中期）：结构化事件门槛，彻底治理

1. 扩展类型定义（`EventOption`）：新增 `requirements` 字段，例如：

- `minRelation?: { npcId: string; value: number }`
- `minMoney?`、`minHealth?`（可复用）

2. `EventModal` 统一读取 `requirements` 进行禁用与原因展示（如“好感不足，需 20”）。
3. 事件数据从“文案门槛”迁移到“结构化门槛”。
4. 增加脚本检查：若文案出现“好感≥”但无 `requirements`，CI 报告告警。

优点：后续新增事件不易漏校验。

### 方案 C（长期）：建立自动审计与回归测试

1. 新增静态审计脚本：扫描 `npcEvents`，输出“疑似文案门槛但无规则”的事件列表。
2. 新增单元测试：
   - 低好感状态下，相关选项应禁用或点击无效；
   - 达标后可正常触发。
3. PR 模板加入检查项：
   - “事件文案中的门槛是否有结构化条件对应？”

---

## 三、执行顺序建议

1. **第 1 天**：完成全量审查清单（事件 ID、门槛文案、当前是否有校验、风险等级）。
2. **第 2 天**：上线方案 A（止血）。
3. **第 3～4 天**：推进方案 B（类型+渲染+数据迁移）。
4. **第 5 天**：补脚本与测试（方案 C），形成防回归闭环。

---

## 四、验收标准

- 所有 NPC 事件中，凡文案写明“好感门槛”的，均有可执行的代码校验。
- `triggerSpecificEvent` 与 `triggerEvent` 的条件判定一致。
- 好感不足时，用户看到明确的禁用原因（而不是“能点但结果异常”）。
- 自动脚本可输出“疑似漏配门槛”列表，便于持续巡检。
